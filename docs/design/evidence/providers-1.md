## Dummy gateway

`POST /v1/providers` created `dummy-gateway` (`kind=gateway`, `baseUrl=http://127.0.0.1:1`, `defaultGateway=true`). The auth token was accepted once. `GET /v1/providers` returned `secret.last4=zzzz` and a 16-hex fingerprint, never the token. Hub `secrets/secrets.json` stayed `0600` and did not contain the token (ChaCha20-Poly1305 nonce/ct only).

`POST /v1/providers/{id}/test` against that dummy URL reported `ok: false`, `reachable: false`, and a message starting with `unreachable:` (connection to `http://127.0.0.1:1/v1/models` failed). The UI shows the same message on the detail row and does not display the token (`••••zzzz last4` only).

## How to enter a real gateway

On **Provider** → **添加网关**:

1. Name
2. Base URL of your Anthropic-Messages-compatible endpoint (include `/v1` if the gateway expects it)
3. Auth token (submitted once; later rotate via **轮换 token**)
4. Optional model list + default model (New Session prefills this)
5. Check **设为默认网关**
6. **测试连通** — a live gateway should list models or at least return HTTP 200/401; dummy URLs stay `unreachable`

New Session → **网关 (gateway)** uses the default profile. Claude launch overlay is generated by `write_claude_provider_overlay` (`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`, `model`) as a `0600` `--settings` file.
