§2.1 待处理置顶
琥珀 pending 优先于 running；待处理永远在顶，不进折叠组 —— 避开「折叠组不汇总待交互」的坑。
状态点是投影
一个点 = lifecycle × activity × connectivity。没有名为 done 的 Instance 点；run 成功只写在 transcript 的 usage 行。
终端入口按 capabilities
行尾「终端」只在 mode=tty-attachable 出现。claude-print 行没有，且永不冒出 Artifact。
不靠 hover
行上所有信息常驻，操作走长按菜单；hover 预览、拖拽排序、常驻 rail 都不下沉到窄屏。
底栏红点 → dust
方案 A 无红色。§1.1 的「红点」用 dust 实现，与 blocked 同源。

动态在哪

effort 落在 member 上

不猜 DAG

和 1g 的结构差别
Claude Workflow 是一个 Instance 内的 run→phase→member；Codex 这套是N 个平级 Instance。所以它不能复用 Workflow 树 —— 每个 attempt 有自己的 journal、worktree、审批、stop。
择优才是这屏的动作
对比表只列拿得到的指标，测试结果由 attempt 自报，拿不到就写「—」不猜。采用 = 合这个 worktree + 停其余，其余 worktree 保留等你清理。
原生 tool 名不改写
commandExecution / applyPatch 复用 Bash / Edit 族的线框，但标题保持原生名 —— 映射在 registry 里，不在文案里。
需要 protocol 补两样
组实体（groupId + 成员 instanceId[]）与 codex 的 DriverKind 取值。图上写的 codex-exec 是占位。
