### 2.2 用户看到的对象分别是什么

| 对象 | 当前含义 | UI 必须保持的边界 |
| --- | --- | --- |
| Host / 主机 | 运行 Node 与原生进程的机器 | 主机在线不代表某个任务成功 |
| Workspace / 工作区 | 某台主机上注册的目录，可关联仓库/worktree 信息 | 用 `hostId + workspaceId` 定位，不能只用名称或单独 ID |
| Space / 空间 | Web 按主机与工作区组合生成的导航分组 | 当前主要是本机浏览器偏好，不承诺跨设备同步或共享成员权限 |
| Instance / 执行实例 | 托管的原生进程及其生命周期、活动、连接状态 | Tab 对应实例；隐藏 Tab、停止执行、删除历史是不同操作 |
| Native session / 原生会话 | 原生 CLI 用于继续工作的身份和记录 | 继续操作创建或返回后继实例，旧实例历史保留 |
| Command / 命令 | 一次输入或控制请求及交付记录 | 受理、发送、结算与任务完成分别表达 |
| Interaction / 待处理交互 | 批准、提问、计划评审等请求 | 回答已提交与原生界面已处理可能有时间差 |

面向用户默认使用“空间、主机、会话”，配置目录时使用“工作目录”；实例 ID、driver、原生 session ID 放入运行详情，保留复制和诊断入口。

依据：[实体模型](../../crates/remuda-protocol/src/entities.rs)、[原生身份](../../crates/remuda-protocol/src/native.rs)、[Spaces 分组与持久化](../../web/src/features/spaces/store.ts)、[继续会话实现](../../crates/remuda-hub/src/http.rs)。当前仅支持 Claude，要求已知原生 sessionId；按实例记录更新时间计算的年龄超过 30 天时拒绝。恢复会创建或复用同主机、同工作区的后继实例，保留旧历史，不能把任意 agent 恢复或跨主机迁移列为现成功能。

## 3. 匿名参考观察与迁移判断

以下是机制级归纳，不是对参考产品能力、稳定性或用户效率的评测。

| 编号 | 本次证据 | 可学习的机制 | 对 Remuda 的应用与限制 |
| --- | --- | --- | --- |
| O1 | 观察：全局导航位置稳定；设置有二级导航 | 用层级和选中态回答“我在哪、这里能做什么” | 延续 Shell，设置内增加分类，保留会话/审批高频入口 |
| O2 | 观察：总览按状态分组，组头有计数和局部新建入口 | 将注意力放在状态与下一步操作 | 强化已有待处理组、匹配数和新建上下文，无需先造新任务系统 |
| O3 | 观察：搜索按对象分组、有快捷键提示；打开获焦，Escape 后返回原焦点 | 可发现的入口解决“知道目标但忘记位置” | 增加跨空间查找，明确所有空间/当前空间范围 |
| O4 | 观察：空间菜单明确当前项和创建入口 | 上下文选择与内容分开 | 保留 Spaces，长列表增加检索和主机标识，不据此引入共享租户 |
| O5 | 观察：设置说明、当前值、操作相邻；基础页未修改时保存/取消禁用 | 操作后果和保存状态贴近操作 | 区分本地即时偏好与服务端配置；未实测参考页保存或权限效果 |
| O6 | 观察：会话详情保留列表，正文有折叠执行摘要、详情入口和底部输入 | 区分读结论、看进展、查细节 | 复用 Transcript、TaskTrack、RawEvents；参考页也出现长运行内容占据正文，不照搬默认展开行为 |
| O7 | 观察：主体用低对比边界分区，主按钮突出，表单不铺满全宽 | 通过对齐、留白和有限强调建立秩序 | 在 Remuda 双主题内调整密度，不复制颜色、品牌或完整布局 |
| D1 | 资料：区分工作上下文、执行过程和结果，提供按执行状态排障的路径 | 让过程可追踪，让排障有下一步 | 增加“当前状态—原因—可做操作”；不把资料描述当执行成功证据 |

推断：这些机制可能减少查找、误操作和排障成本。尚未进行对照测试，不声称已经提升某个百分比。

## 4. 目标体验

围绕四个问题设计：**在哪执行、现在什么状态、需要我做什么、结果和细节在哪里。**

宽屏继续使用“全局导航 → 空间/会话导航 → 主内容”。标题附近显示上下文与状态；正文优先呈现消息、待处理请求和执行摘要；运行详情按需打开。手机用已有空间抽屉和全屏详情路由承载同一信息，避免常驻多栏。

```text
全局导航       空间与会话                 当前会话
会话           搜索所有空间…              示例项目 / 示例会话   运行中
待处理         示例项目 · 测试主机        对话  终端  运行详情
新建             会话甲 · 等待回答        [需要你回答：查看问题]
管理             会话乙 · 运行中          [消息与执行摘要；细节按需展开]
设置           另一个示例项目            [输入；当前权限；发送/引导行为]
```

示意只表达 Remuda 的信息层级，不是视觉稿，也不要求同时重写导航和会话渲染。

## 5. 具体改进规格

### P0-1：筛选、范围与零结果反馈

代码事实：`SessionList.tsx` 第 167–169 行的筛选按钮没有绑定动作；第 174–247 行的多维选项持续展开。空分组直接不渲染，没有“有会话但筛选后零结果”的专用反馈。当前列表被选中 Space 限定，却展示所有主机/工作区筛选选项，可能形成互相排除的条件。

提案：

1. 默认显示搜索框、当前范围、匹配数和已选条件；筛选按钮打开桌面 popover 或手机 sheet。
2. 当前 Space 模式显示固定范围，不提供跳出该 Space 的主机/目录条件；全局模式通过明确入口进入。
3. 保留 URL 为条件事实来源。搜索输入替换历史项，明确提交的条件变更可返回；刷新/深链/返回保持条件与结果一致。
4. 区分无主机、无工作区、无会话和无匹配结果。零结果提供“清除筛选”和“搜索所有空间”。
5. 切换 Space 清理不适用的主机/目录条件，保留仍有意义的文本/状态条件并显示出来。

验收：点击和键盘均能展开/关闭，`aria-expanded` 正确；同名跨主机工作区、零结果、深链/刷新/返回 fixture 结果确定；清除条件不创建或关闭会话。

### P0-2：新建会话的上下文、焦点与草稿

代码事实：新建页使用自有遮罩和 form，缺少统一 dialog 语义、Escape 和 Tab 圈定；关闭固定返回 `/sessions`；提示词从空字符串开始。部分首层文案暴露 `InstanceSpec`、driver 等实现字段。已有 Composer 草稿和移动抽屉焦点行为可复用。

提案：

1. 首层围绕“要做什么、工作目录、执行 agent、权限、开始”；模型与努力程度有可见摘要，原始 ID、carrier/provider 进入高级设置。
2. 共享 dialog/sheet 具备名称、`aria-modal`、初始焦点、Tab 圈定、Escape、触发器焦点返回。不得让焦点进入遮罩后的可操作页面。
3. 记录打开来源及空间。取消回原会话/列表；直接访问新建深链时回该空间列表；来源失效时有稳定回退。
4. 草稿按应用来源、可靠登录身份及 `hostId + workspaceId` 隔离；无可靠身份时只放当前页内存。持久内容限定正文与非敏感选项，不保存认证值、临时文件内容或附件二进制；沿用现有本地草稿策略。
5. Escape/遮罩关闭保留可恢复草稿，显式“丢弃草稿”才清除；失败保留输入。创建确认后由会话页显示初始输入的实际状态，避免重复创建。
6. 主机离线或无注册目录时说明原因并链接管理入口，不自动选择任意路径。高权限选项的后果仍在用户决策处说明。

验收：从会话打开并取消返回原处；仅键盘可完成操作；重开恢复同一上下文草稿，切换主机/账户不串用；未知 ACK 不自动再次创建；手机软键盘不遮挡主操作。

### P0-3：按事实阶段显示异步结果

代码事实：Shell 的 toast 2.4 秒后消失，普通 div 没有 live region；部分恢复/删除失败和延迟清理依赖短反馈。后端已区分命令状态、发送状态和结果，应在 UI 保留这些差别。

提案：轻量成功反馈可短暂出现；阻断错误、不确定状态、待处理请求在发生位置持续显示。通知包含对象、阶段、原因与可用动作；复制诊断仅包含脱敏后的必要信息。

| 已知事实 | 建议用户文案 | 可用动作与限制 |
| --- | --- | --- |
| 在队列，尚未发送 | 等待发送 | 查看原因；若支持可取消未发送请求 |
| 已受理或创建命令完成 | 已受理 / 会话已创建 | 展示后续启动/输入状态，不能显示任务成功 |
| 写入传输但原生确认未知 | 已发送，等待确认 | 查看状态，不能自动重发原生输入 |
| 缺 ACK、断线或调和中 | 状态待确认 | 刷新观测/诊断；刷新不产生新发送 |
| 有待回答交互 | 需要你回答 / 需要批准 | 打开同一个 Interaction |
| 回答已提交但原生未清除 | 回答已提交，等待处理 | 旧请求不再可重复提交 |
| 有可靠原生结束事实 | 本轮已结束；结果按已知 outcome 说明 | 不用 terminal idle 或普通命令 settled 推断业务成功 |
| Hub 会话记录已删除，但 Node 数据清理未确认 | 会话记录已删除，主机数据待清理 | 保留独立清理提示或审计结果，不恢复已删除会话；只有可查询事实支持时展示后续清理完成 |

表格是展示规则，不是一条所有驱动必经的线性状态机。前端从现有事实字段投影，不用动画或猜测补齐未知状态。依据：[协议枚举](../../crates/remuda-protocol/src/enums.rs)、[PTY 队列](../../crates/remuda-node/src/runtime/pty_queue.rs)、[交互展示状态](../../web/src/lib/interactionStatus.ts)。

普通反馈使用 `role="status"` 等适当机制，阻断错误有可发现的错误区域；不要把整个流式正文放入高频播报区域。重试限定读取或确认未派发且契约允许的动作。已知服务端 commandId 时，只查询该命令及相关观测；响应前失败、尚无可靠 commandId 时保留“状态待确认”，不按内容猜测关联，也不自动重发。当前前端先创建本地 bubble ID，收到响应才绑定服务端命令身份；若需可靠关联，应单独补客户端请求身份与服务端调和契约，不能把本地 ID 当作服务端 commandId，也不承诺自动重发的 exactly-once。

验收：模拟断线、慢确认、拒绝、并发回答、延迟清理；刷新不新增原生动作；关键错误不被下一条成功 toast 覆盖；已答请求不能二次提交；列表/Tab/详情使用一致状态词汇。

### P1-1：跨空间快速查找

代码事实：SessionsPage 只将当前 Space 实例交给列表，SpacesPanel 没有检索入口。推断：会话增多时，忘记归属的查找成本会上升，尚未测量。

提案：提供常驻搜索和桌面快捷键提示，结果按会话、空间、主机分组；会话行包含空间、主机、状态和最近时间。第一期只检索已加载的可访问元数据并明确范围，不暗示可以搜索全部历史正文。优先匹配标题、空间名和主机名，ID 辅助命中。

打开获焦，方向键选择，Enter 打开，Escape 返回原焦点。保留现有 Cmd/Ctrl+B、数字快捷键、input/contenteditable/xterm 保护；不截获终端原生输入。手机有同等入口与结果模型。

验收：同名会话由空间/主机区分；跳到正确实例；无结果有恢复路径；取消不改变空间选择；离线说明只搜索缓存；返回恢复原会话与导航上下文。

### P1-2：会话阅读、执行摘要与详情分层

代码事实：Transcript 已有虚拟化、折叠、跳到最新和任务轨迹，尚无结构化正文搜索。TaskTrack 可直接展示长 prompt；详情头部常驻部分诊断字段。无需另建消息组装器或运行日志。

提案：

1. 正文保留用户消息、助手输出、待处理交互；执行摘要展示已知阶段、工具数量或子任务状态，按需展开现有细节。没有可靠阶段时只呈现已知事实，不造进度百分比。
2. driver、原生 ID、交付证据放入运行详情。工具失败和权限请求有直接入口，不能因折叠失去可发现性。
3. 搜索基于组装后的已加载节点，不依赖浏览器查找虚拟 DOM。用稳定内容身份定位并滚动挂载节点，提供匹配数、上一项/下一项和退出。
4. 明确“已加载历史”范围；更早记录沿用 journal backfill。修订/追加到来时保持当前命中身份；退出恢复阅读位置和跟随状态。
5. 手机有搜索、运行详情及返回入口，正文和终端使用各自合适的搜索方式。

验收：2,000-event fixture 可命中当前窗口外的已加载消息；修订不跳错节点；退出回原位置；工具失败可见；正文/终端切换不启动额外进程；搜索不改变 journal 或原生 session。

依据：[Transcript](../../web/src/features/session/Transcript.tsx)、[assemble](../../web/src/features/session/assemble.ts)、[TaskTrack](../../web/src/features/session/TaskTrack.tsx)。

### P1-3：设置分组与视觉基础

代码事实：设置集中处理设备、凭据、外观、默认行为和通知；已有单一路由，缺少稳定页内分类。主题 token 和焦点样式已有，组件仍分散使用小字号及 32/40/44px 等不同交互尺寸；尚未实测并宣称可访问性违规。

提案：

- 先保留 `/settings`，增加“外观与输入、通知、连接与登录”分组导航和锚点；主机、工作区、Provider 保持现有管理页。手机用页内分类入口，返回保留位置。
- 本地即时偏好明确“仅此浏览器”；服务端操作说明保存中、已保存、失败。不把本地存储标注为已同步，不新增无后端实体支持的成员角色页。
- 复杂输入统一有说明/错误反馈的 dialog；权限或不可逆操作保留明确后果说明，不为减少点击绕过授权。
- 保留 night/ledger 和字体，补齐字号、间距、状态文字、焦点及触摸目标 token。建议正文 14–16px、辅助信息 12–13px，重要状态不依赖 10px 文字或单一颜色；这些是待实测调整的设计目标。
- 手机关键操作按项目既有 44px 目标统一，包括 Space chips 和 ActionSheet；图标与命中区域可以不同尺寸。减弱重复边框，突出当前项、待处理和主操作。

验收：双主题、200% 缩放、390/768/1440px、触摸模式检查；焦点可见；设置失败可恢复旧有效值；深链/返回有效；不新增默认权限。

依据：[SettingsPage](../../web/src/pages/SettingsPage.tsx)、[Spaces 样式](../../web/src/features/spaces/spaces.module.css)、[全局 token](../../web/src/styles/tokens.css)。

### P2-1：文件结果视图先明确数据契约

代码事实：已有 `/s/:instanceId/files` 路由，正文仍是文件/diff 占位；桌面入口存在，手机等价入口需补齐。不能用未经证实的“本次改动”列表替换占位。

第一步交付是契约决策：确认数据来源、访问范围、基准 revision、路径、内容 digest、所属实例/会话、截断标记与可用状态。工具输出中的路径或当前工作树 diff 都不能直接证明本次会话产生了文件改动。

数据可用后先只读展示有来源的文件与 diff，区分无变化、尚未采集、不支持、权限不足、离线。宽屏按需面板，手机全屏 route，返回保持正文位置。若只有当前工作树状态，标题应为“工作区当前变更”，不能归因给某次会话。

访问继续受注册目录、路径规范化、权限边界约束，不扩展为任意文件浏览/编辑器。原始内容可能有敏感信息，公开截图只用合成 fixture。

进入实施条件：数据源和授权策略形成可审阅契约。若无可用来源，以准确的不可用说明结束勘察，不用虚构数据验收。验收覆盖合法文件、越界、无变化、不支持、离线、截断与内容变化；查看 diff 不修改文件或执行命令。

依据：[文件占位](../../web/src/pages/SessionPage.tsx)、[工作区约束](../../crates/remuda-node/src/workspace.rs)。

## 8. 风险、待定项与回退

| 待定项 | 默认选择 | 调整依据 |
| --- | --- | --- |
| 是否需要远程搜索索引 | 第一期只查已加载可访问元数据，明确范围 | 历史量/延迟显示不足，再设计授权过滤、分页、索引 |
| 设置是否拆新路由 | 保留路由，锚点分组 | 分享/返回需求超出页内导航能力 |
| 新建草稿保留期限 | 沿用现有本地策略，按身份/工作区隔离；身份不明只存内存 | 登录与共享设备要求更严格清理时，定义过期与迁移 |
| 执行摘要如何分组 | 只展示可确认事实，失败保持可见 | 大型会话需要额外分组时，设计稳定身份和展开状态 |
| 文件“结果”如何归因 | 数据契约明确前不归因，可标注工作区当前变更 | 有可靠 session/turn、基准 revision 和来源关系 |
| 是否整体重做视觉 | 在现有主题内统一层级和命中区域 | 用户任务证据表明现有布局无法支持关键工作流 |

回退按批次进行：搜索、面板、分组回到原组件与路由；新增本地偏好使用独立版本键，不破坏原 Spaces 数据；草稿迁移不含凭据。不要为 UI 回退改写旧 journal、原生 session 或命令历史，也不能把未知状态重新显示成成功。
